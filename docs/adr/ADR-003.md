# ADR-003 — Migração da stack para Node.js

- **Status:** Aceita
- **Data:** 2026-10-23
- **Substitui parcialmente:** ADR-001 (itens 1, 3 e 4)

## Contexto
Na Sprint 0 o Python do ambiente do usuário (Windows/PowerShell) não pôde ser executado: o alias da Microsoft Store retorna "Python não foi encontrado" e `py` retorna "Acesso negado". Node.js, npm e Git já estão operacionais (Node v22.19.0, npm 10.9.3). Nenhum código de aplicação havia sido escrito.

## Decisão
1. **Node.js (LTS, ESM, JavaScript)** como único runtime, backend e frontend, com `npm`. Sem Python, venv ou pip. Exigir Node LTS ≥ 20; recomendar ≥ 22.
2. **Backend:** Express 5 + `better-sqlite3` (arquivo local `backend/data/capacitacoes.db`) + `zod` para validação. SQL escrito à mão em `db.js`/serviços, sem ORM.
3. **Testes do backend:** Vitest + supertest. A aplicação exporta `createApp(db)`; cada teste usa SQLite em memória (`:memory:`).
4. **Frontend:** React + Vite, CSS puro com variáveis (ADR-002 inalterado).
5. **Portas:** API em `8000` (variável `PORT`), frontend em `5173`; CORS liberado para `http://localhost:5173`.
6. **Raiz:** `package.json` com scripts `install:all`, `dev:backend`, `dev:frontend`, `dev` (ambos, via `concurrently`), `test`, `build`.
7. **Erros:** validação zod → 422; conflito de regra → 409; inexistente → 404; formato `{"detail": "..."}`.
8. **Plano B (não implementado):** se a instalação do `better-sqlite3` falhar no Windows, usar o módulo nativo `node:sqlite` (Node 22.5+), trocando apenas `db.js`; registrar novo ADR somente se acontecer.
9. **PostgreSQL:** continua só como evolução documentada (trocar a camada `db.js` por `pg`).

## Consequências
- Um único gerenciador de pacotes e ambiente; menos risco de bloqueio de ambiente.
- Escopo funcional, entidades, RN01–RN08, endpoints/contratos, indicadores, telas, design, 3 sprints, CA-01 a CA-03, T01–T14 e regra de Git permanecem.
- Os itens 2, 5, 6, 7 e 8 da ADR-001 continuam válidos.
