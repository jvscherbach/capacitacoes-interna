# Prompt — Sprint 0 (Claude Code)

Estamos na pasta do projeto **Capacitações internas**. Leia `HANDOFF_CLAUDE_CODE.md`, `CLAUDE.md` e todos os arquivos em `docs/` (incluindo `docs/adr/ADR-003.md`: stack Node.js).

1. Primeiro, liste decisões e dúvidas. Não mude o escopo sem registrar um ADR.
2. Revise `docs/REQUISITOS.md`, `docs/ARQUITETURA.md`, `docs/BACKLOG.md` e `docs/TESTES.md`; corrija apenas inconsistências reais entre eles e registre o que mudou.
3. Crie a estrutura: `backend/` (com `src/`, `data/`, `tests/`), `frontend/` e `.gitignore` (`node_modules`, `dist`, `backend/data/*.db`, `.env`). Remova arquivos e pastas de uma stack anterior, se existirem (ex.: `tests/` na raiz), e registre.
4. Crie `package.json` na raiz (scripts `install:all`, `dev:backend`, `dev:frontend`, `dev` via `concurrently`, `test`, `build`) e `backend/package.json` (`"type": "module"`; dependências: express, better-sqlite3, zod; dev: vitest, supertest). O `frontend/package.json` fica para a S2.
5. Verifique Node (LTS ≥ 20; recomendado ≥ 22), npm e Git (somente `--version`); prepare instruções Windows/PowerShell no esqueleto do `README.md` (incluindo `npm.cmd` / `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`).
6. Faça **apenas a Sprint 0**. Não escreva código de negócio. Se for necessário validar que `better-sqlite3` instala no Windows, rode `npm install` no backend e registre o resultado real (se falhar, informe antes de adotar o plano B da ADR-003).
7. Registre comandos executados e resultados reais em `docs/EXECUCAO.md` (seção Sprint 0) e marque a S0 como CONCLUÍDA no `docs/BACKLOG.md` somente se o gate passou.
8. Não inclua segredos. **Não execute comandos git de escrita** (nem `git init`); proponha a mensagem de commit em `docs/EXECUCAO.md`. Só `git diff` é permitido.

Ao final, informe o que foi realmente validado e o que ficou **NÃO TESTADO**.
